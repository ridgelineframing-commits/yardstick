# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Yardstick — PDF plan markup + material takeoff for residential construction (Ridgeline). A
single self-contained HTML file wrapped in a thin Tauri v2 shell for a Windows installer, and
also published as-is to GitHub Pages as an installable PWA. No framework, bundler, or backend —
plain HTML/CSS/JS driving an SVG overlay on a canvas.

## Architecture — the big picture

```
app/index.html   <- THE SOURCE OF TRUTH. Whole app: UI, calibration, tracing, auto room-
                     detect, PDF text scan, exporters. Loads pdf.js / xlsx / jsPDF from CDNs,
                     so this file alone also works as a plain web page (this is what GitHub
                     Pages serves, unmodified, on every merge to main).
src/index.html   <- GENERATED by update-src.js from app/index.html. Gitignored — NEVER edit
                     directly, your changes will be silently discarded on the next build.
src/vendor/      <- Offline copies of pdf.js (pdf.min.js + pdf.worker.min.js), xlsx-js-style
                     (xlsx.bundle.js), and jsPDF (jspdf.umd.min.js), checked in so the desktop
                     build needs no internet at runtime.
src-tauri/       <- Tauri config + Rust entry point (main.rs just opens the WebView), icons,
                     NSIS bundle target.
update-src.js    <- Copies app/index.html -> src/index.html, rewriting each CDN <script> URL
                     (see the REWRITES table in the script) to its src/vendor/ path. Fails loudly
                     if a vendored lib is missing, or if any CDN reference survives the rewrite
                     (a leftover CDN reference would white-screen the offline desktop app).
```

**Always edit `app/index.html`.** `src/index.html` is a build artifact, not a second copy to
keep in sync by hand — `update-src.js` regenerates it wholesale every time.

Tauri wires `update-src.js` in automatically via `beforeDevCommand` / `beforeBuildCommand` in
`src-tauri/tauri.conf.json`, so both `npm run dev` and `npm run build` always regenerate
`src/index.html` from the current `app/index.html` before running — there is no separate sync
step to remember.

**Version single-source-of-truth**: bump `version` in `package.json` only. `tauri.conf.json`
reads it via `"version": "../package.json"` — don't set the version in `tauri.conf.json` or
`Cargo.toml` directly (the older `README-BUILD.md`, describing a since-restructured layout, says
otherwise; `package.json` is what's actually wired up now).

## Commands

```bash
npm install
npm run dev      # tauri dev — regenerates src/index.html, opens the app in a native window, hot-reloads on save
npm run build     # tauri build — regenerates src/index.html, then packages the NSIS installer
npm run update-src  # just the regeneration step, standalone (node update-src.js)
```

No test suite / linter is configured (no `test`/`lint` script in `package.json`).

Building the Windows installer requires Node.js, Rust, and the MSVC C++ Build Tools (see
`README-BUILD.md` for one-time setup). The installer lands at:

```
src-tauri/target/release/bundle/nsis/Yardstick_<version>_x64-setup.exe
```

CI (`.github/workflows/build.yml`) runs a fast Ubuntu `verify` job on every push/PR (regenerates
`src/index.html`, confirming no CDN reference leaks through), plus a `windows` job that runs the
real `npm run build` and uploads the installer as an artifact, attaching it to the GitHub Release
on `v*` tags. `.github/workflows/pages.yml` deploys `app/` as-is to GitHub Pages on every push to
`main`.
